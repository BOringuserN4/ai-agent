## 一、一句话结论

> **结构是对的，但内容还不全面。**
> 它现在是一本很好的「**我如何手写一个 Agent**」的书，
> 还不是一本「**Agent 工程全景**」的书。

粗略估计（主观）：

- 对“手写一个能跑、能评测的单/多 Agent”：覆盖约 **80%**；
- 对“Agent 工程全景”：覆盖约 **55–60%**。

---

## 二、结构评价

### 强项

1. **主线成立**：本质 → 记忆 → 编排 → 工程化 → 边界 → 下一步。
2. **不堆模式，给实测和负结果**：EC 0/6、rerank 被否决、Planner 被否决、
   Blackboard 只调查——这些比“十大模式”值钱。
3. **有贯穿全书的主角**：`minimal.py` 的 88 行，每篇在它身上加东西。
4. **有代价意识**：多 Agent 是成本结构、记忆不是越多越好、契约看消费方。

### 偏差

> **它更像“项目实验精选”，还不是“Agent 设计空间导论”。**

它讲清了“这条路线怎么走”，但没有先给读者一张
“整个 Agent 领域有哪些岔路”的地图。
读者读完会做这一套，但未必知道还有哪些选择、什么时候该选别的。

## 四、关键遗漏

### P0：不补就不像“入门全景”

| 缺口 | 为什么重要 | 建议位置 | 最小交付 |
|---|---|---|---|
| **上下文工程** | token 预算、prompt 分层、压缩、工具 schema 预算，决定长任务能不能跑 | 第 4 讲 | 1 章 + 1 张 token breakdown 图 + 1 次 history 增长/截断实验 |
| **评测 rigor** | 现有 golden set 只有 14 条、n 小；满分不等于评测有效 | 第 26 讲 | 1 章 + n/置信区间/判分器偏差 + 1 个回归门 demo |
| **安全 / 权限** | prompt injection、工具注入、数据外泄、沙箱、审批，是工具型 Agent 的底线 | 新增一章（可并进第 32 讲） | 1 章 + 1 个注入 demo + 1 个审批/沙箱 demo |
| **长任务 / 状态** | 没有 checkpoint/resume，Agent 只能停在“一次会话” | 第 32 讲 | 1 章 + RunState/checkpoint/resume 设计 + 1 个恢复 demo |

> 你的待写清单（第 4、26、32 讲）已经命中了最大的三个洞；
> 安全目前连“待写”都还没列进去。

### P1：不补结构不完整

| 缺口 | 为什么重要 | 建议位置 | 最小交付 |
|---|---|---|---|
| **规划 / 控制** | 你否决了 Planner，但没有正面讲“什么时候规划才值” | 第 15 讲前后 | 1 章：ReAct vs Plan-Execute vs Reflexion/Tree Search；用现有负结果当案例 |

## 五、结构改进三条

1. **加一张“设计空间地图”**  
   在第三篇开头或序章放一张表：模型、上下文、工具、记忆、规划、控制、
   多 Agent、评测、安全、运维。  
   让读者知道：你这条 Router/Worker 路线只是其中一种配置，不是唯一答案。

2. **每章结尾加一句“这是其中一种选择”**  
   比如记忆用 Chroma + DashScope，是案例，不是标准答案；
   编排用 Router/Worker，是成本结构下的一种选择。  
   这样书不会把“项目选择”误写成“领域共识”。

3. **加一节“这本书不覆盖什么”**  
   放在序章。诚实列出：安全、长任务、规划、工具设计、UX、生产运维。  
   这不会削弱书，反而会让它更像一本可信的教材。

## 七、不要做什么

- **不要变成 survey**：这本书的独特价值是“手写 + 实测 + 负结果”，
  不是“把 20 个框架各介绍一遍”。
- **不要为了覆盖而丢掉负结果**：EC 0/6、rerank 否决、Planner 否决，
  比多写三种模式更有价值。
- **不要把所有章节写成同一种模板**：实验章、概念章、案例章，
  应该有不同的写法；但每章都要有“前因后果”。

## 八、判断标准

补完之后，用这 6 个问题自检：

1. 读者能画出 Agent 的设计空间，而不只是记住 Router/Worker 吗？
2. 读者能说清“模型看到了什么、上下文花在哪”吗？
3. 读者能判断“这个评测结果可不可信”吗？
4. 读者能在加工具前，先设计权限/审批/沙箱吗？
5. 读者能区分“一次会话”和“长任务”吗？
6. 读者能说出“什么时候不该加”吗？

> 这 6 个问题答上 5 个，这本书就从“项目实验精选”
> 变成“Agent 入门全景 + 一条可复现的实践路线”。
