> 中心目标：**把 Agent 的整个流程学会、学懂、学透**。
> 这份盘点不按“名词”分类，按“你能不能独立画出/跑出/讲清这条流程”分类。

## 一、一句话结论

> **主干已经打通，缺的不是“更多模式”，而是“流程的四个缝”：
> 上下文怎么装、token 怎么流、工具怎么失败/恢复、评测怎么可信。**
> 把这四个缝补上，再回头看可视化，事件表自然就有了。

## 二、已经学过的（按能力层）

| 能力 | 代表讲义 | 状态 |
|---|---|---|
| Agent 本质 / ReAct / 最小循环 | 能力阶梯、`minimal.py` | ✅ **学透**：能讲清“一个循环 + 一份工具清单” |
| 工具调用 / function calling | `tools.py`、MCP基础 | ✅ **会用**：能加工具、能解释调用回流 |
| 短期/长期记忆 | 记忆抽取、召回修复、切分、用例评测 | ✅ **会用**：Chroma + embedding + 阈值 + 抽取 |
| 多 Agent 拆与不拆 | 编排模式、学习总结 | ✅ **学透**：四条判据、成本结构 |
| 编排模式 | 编排模式 + 各调查 | 🟡 **8 实现 / 1 只调查 / 1 否决**（见下） |
| 评测 / 可观测 | 学习总结、问题清单、Langfuse | ✅ **会用**：golden set + judge + trace |
| 成本优化 | 路由成本优化、MCP基础 | ✅ **会用**：预筛 / 工具裁剪 / 清声明 |
| 协议 | MCP基础、MCP边界 | ✅ **会用**：server + bridge + 裁剪；进阶未学 |
| 约束与收尾 | 约束与收尾 | ✅ **学透**：截断 + 预警 + ANSWER_STEP |
| 感知结构化 | 感知结构化调查 | ✅ **学透**：`{ok,data,error}` 契约 |
| 能力 × 编排 | 能力与编排对照、正测设计 | 🟡 **只调查**：gap 造出来了，正测暂停 |
| 可视化 | 交互可视化设计 | ⬜ **只有设计稿** |

### 编排 10 种，实际深浅不一样

| 模式 | 状态 |
|---|---|
| Router / Pipeline / Fan-out / EC | ✅ 实现 + 实测 |
| 工人池（层级） | ✅ 条件性实现（慢工具才值；不是完整多级） |
| Group Chat / Contract Net / Debate | ✅ 实现 + 实测（Debate 必要性未复现） |
| Blackboard | 🟡 **只调查**，没实现为模块 |
| Planner-Executor | ❌ **实测否决**（小任务无病；长链救不了） |

> 所以“10 种全覆盖”是**碰过**，不是“每种都实现且都值得用”。
> 这句话对“学透”很重要：**知道哪种不该用，比会用 10 种更值钱。**

## 四、完全没学 / 只提到的专题（按优先级）

### P0：补“流程的四个缝”（建议未来 3 天）

| 专题 | 为什么重要 | 当前状态 | 建议产出 |
|---|---|---|---|
| **上下文工程** | 模型的行为由“窗口里有什么”决定；现在只有 `trim_history` | 只做了最基础的丢旧消息 | 一页“窗口里到底装了什么” + 压缩/排序/缓存方案 |

## 五、未来几天：3 天核心 + 2 天延伸

> 每天 2–4 小时读 + 2–4 小时动手；产出都落到文档/事件表，不追求“看完”。

### Day 1：上下文工程 + 流式

**读**：`core.py` 的 messages 装配 / `trim_history`、`memory.py` 的注入、OpenAI streaming 文档。

**做**：
1. 写一个只读脚本，打印一次 run 的“窗口快照”：system / memory / history / tool results / token 估算。
2. 写一个 20 行 streaming spike，把 token 增量打到终端。
3. 记下 `context_built` / `llm_delta` 两个事件。

**产出**：一页“窗口里装了什么” + 30 秒流式 demo。

**验收**：能解释“为什么第二次 LLM 调用的 prompt token 变多了”。

### Day 2：工具生命周期 + 状态/恢复

**读**：`tools.py`、`core.py` 工具循环、`observation.py`、`multi_agent.py`。

**做**：
1. 列一个工具错误矩阵：超时 / 异常 / 空结果 / 被截断 / 权限拒绝。
2. 设计 `RunState`：messages、step、usage、pending_tool_call、status。
3. 模拟一次“序列化 → 恢复 → 继续跑”。

**产出**：状态机图 + 错误矩阵。

**验收**：能说清“工具失败时，状态停在哪、下一步怎么走”。

### Day 3：评测 rigor + 安全/审批

**读**：`golden_set.py`、`judge.py`、`eval_runner.py`、记忆用例、约束与收尾。

**做**：
1. 给现有结果补 Wilson 区间（0/6、4/5、18/18 等）。
2. 抽 10 条 judge 结果做人工校准，看判分器是否漂。
3. 列 3 个 prompt injection 入口 + 工具权限矩阵 + 人工审批门。

**产出**：带 n/CI 的评测表 + 威胁模型 + 审批流程。

**验收**：能说“0/6 在 n=6 下意味着什么”；能说出 3 个注入入口。

### Day 4（延伸）：A2A / MCP 进阶 + LangGraph 对照

- 读 MCP 的 resources / prompts / sampling / auth；A2A 概览；LangGraph 的节点/边。
- 把你的 Router/Worker 映射成 LangGraph 的 node/edge，做一张对照表。
- 产出：一页“我的编排 vs 框架编排”。

### Day 5（延伸）：可视化 P0/P1

- 把 Day 1–3 的事件拼成事件表。
- 只做 `minimal.py` 的单次回放：上下文 → LLM → 工具 → 回答。
- 产出：60–90 秒回放。

> 可视化不是新专题，是**把前四天学到的流程拍下来**。
> Day 1 的 `context_built`、Day 2 的 `tool_*`/`run_resume`、Day 3 的 `score`/`approval`，
> 正好是 P1 的素材。

## 六、我建议现在**不要**做的

1. **不要一上来学 LangGraph 全家桶**：先把自己的 10 个事件画清楚；框架只是另一种壳。
2. **不要再加第 11 种编排模式**：10 种已经够多，缺的是 flow 的缝。
3. **不要先做多模态 / 部署 / 大而全的看板**：离“学透流程”太远。
4. **不要把可视化当主线**：它是相机，不是路；路是上下文、工具、状态、评测。
