## 一、这本书写给谁

- 会一点 Python，用过 LLM API，但没写过完整 Agent 的人。
- 写过 demo，但不知道“下一步该加什么、加了付什么代价”的人。
- 不想一上来学 LangGraph/CrewAI，想先看懂 Agent 本质的人。

**承诺**：读完能自己写出一个可运行、可评测、可解释的 Agent；
知道每种结构**什么时候该加、加了付什么代价**。

**不承诺**：不教你调参、不教你追 SOTA、不教你部署一个生产平台。

## 二、叙事主线（五拍）

> **LLM 只会“说”；Agent 通过一层层闭合回路，把“说”变成“做”。**

```
只会说（开环）
  → 能动手（工具）
  → 能看结果（感知）
  → 能记住（记忆）
  → 能组织（编排）
  → 能验证/收束（评测与约束）
  → 能看清自己（可观测/可视化）
```

每一拍都遵循同一个句式：

> **上一拍留下了什么问题 → 这一拍补哪条回路 → 补上之后多付什么代价 → 下一拍为什么还存在。**

### 贯穿全书的四条线

1. **主角**：`minimal.py` 的 88 行 Agent。每章在它身上加一样东西，并测“加之前/之后”。
2. **反复出现的问题**：这一步模型看到了什么？它为什么这么走？代价是什么？
3. **反线**：被证伪的判断（规划、rerank、Debate、Blackboard、同模型 EC）——
   告诉读者“什么时候不该加”。
4. **收束**：从教学项目到 harness（事件日志/门禁/可视化），但保留白盒。

## 五、现有文档的问题（这次要修）

1. **章节像独立论文**：每篇都有“是什么/代价/实测”，但缺少“上一章留下什么、下一章为什么存在”。
2. **概念重复**：Router/EC/记忆在多篇重复解释；没有统一术语表与交叉引用。
3. **同一个实验分散**：EC 在 `编排模式`、`数值题 EC`、`学习总结` 各讲一遍；
   记忆在 `抽取/召回/切分/用例` 各讲一遍。需要“主叙述 + 引用”。
4. **元文档混在正文**：`问题清单`、`文档审视报告`、`文档重构方案`、`学习盘点`
   是维护文档，不是书的内容；应进附录/后记。
5. **阅读顺序按主题，不按问题**：读者不知道“为什么现在读这篇”。
6. **部分章节缺钩子**：`rerank`、`本地推理`、`向量模型升级` 更像“实验记录”，
   需要先回答“它在全书哪个问题下”。
7. **术语不统一**：编排四模式 vs 10 种；多 Agent vs Multi-Agent；记忆 vs 上下文。
8. **图是单篇插图，不是全书插图**：图号、风格、引用需要统一。

## 六、章节模板（以后每章按这个写）

```markdown
# 第 N 章 标题

> **前情提要**：上一章留下了什么问题？
> **本章只回答**：一句可证伪的问题。
> **读完后你能**：...

## N.1 为什么现在需要它
（不解释“它是什么”，先讲“没有它会怎样”）

## N.2 它怎么工作
（一张图 + 一段代码 + 一个最小例子）

## N.3 代价
（token / 延迟 / 复杂度 / 失败模式；必须具体）

## N.4 实测账
（日期、n、模型、数字；正结果与负结果并列）

## N.5 常见误解
（读者最可能想错的地方）

## N.6 本章小结 & 下一章为什么存在
（一句结论 + 一个钩子）

## 自检 3 题
1. ...
2. ...
3. ...
```
