# AI Agent 教学工作流

> 本 skill 是**流程**；硬约束在仓库根的 `AGENTS.md`。开工前先读 `AGENTS.md`。
> 这个仓库的目标是"看懂 + 测出来"，不是"代码更多"。

## 0. 开工前先答五问

1. **这次要证伪哪一句话？** 写成一句可判真假的话，带阈值。
   例：`EC 对弱模型的提升比强模型高至少 20 个百分点`。
2. **病存在吗？** 最小复现是什么？先跑现状臂，不先写方案。
3. **自变量 / 因变量是什么？** 怎么**确定性**判分？哪些只能人工？
4. **baseline 是什么？n 多少？预算多少？** 没有 baseline 不许说"提升"。
5. **结论成立 / 不成立分别长什么样？** 先写决策规则，再看数据。

如果五问答不齐，先别动手；把问题写进 `docs/02-编排章/` 下的调查笔记。

## 1. 实验协议（最小版）

- **单变量**：一次只改一个东西；其余（prompt、temperature、max_tokens、工具集）固定。
- **n≥5**：n=1 只能当 smoke；n=3 只能写"方向性"。报告 n。
- **判分器先自测**：用 10 条已知答案验证判分器；再跑实验。
- **三态**：`OK` / `WRONG` / `ERR`。`ERR` 是跑挂（429/超时/空输出），
  **不计入分母**，单独报告；不要把 `ERR` 当 0 分。
- **原始数据落盘**：`tmp-artifacts/`（gitignored），一行一个 run，含
  时间、模型、prompt 版本、token、墙钟、原始输出、判分状态。
- **先定停止条件**：预算上限、连续 ERR 上限、单 cell 最长时间。
- **随机化/交错运行顺序**：避免"先跑的 cell 赶上模型高峰"。
- **先重跑 baseline**：模型会漂移；旧数字不能直接当今天的 baseline。

### 常见失效模式（写进设计时逐条对照）

| 失效 | 症状 | 对策 |
|---|---|---|
| 题集天花板 | 两个模型/两臂都满分 | 加难例，先让 baseline 有 gap |
| 打分器假阳性 | 数字整齐得可疑 | 看原始输出；抽 10% 人工复核 |
| 只统计准确率 | "58% 还行"，其实该记的全漏 | 分方向统计：漏/误/错 |
| 测试集泄漏 | 提示词就是测试查询 | 用留出集；提示写通用问法 |
| 退化扫描 | 参数怎么变结果都一样 | 先查扫描是否真的生效 |
| 期望值算错 | 数字很整齐 | 手算/独立脚本复核 |
| 把构造时间算进计时 | 差异被稀释 | 计时区只含被测行为 |
| 单次测量当结论 | 补测就消失 | n≥5；报区间 |

## 2. 讲义模板（六段）

```markdown
# 章名

**一句话**：...
**适读**：...
**相关讲义**：...

## 1. 是什么
## 2. 结构定位
（谁控制流 × 信息怎么流）
## 3. 为什么这么设计
（替代方案为什么不行）
## 4. 代价（值钱那行）
（token/延迟/复杂度/维护/失败模式，边界在哪）
## 5. 代码在哪
（文件 + 类/函数）
## 6. 怎么跑
（可直接复制的命令）
## 7. 实测账
（日期、n、模型、token、墙钟、分数；不是估计）
## 8. 踩过的坑
```

写讲义前先读 `docs/00-索引/成文规矩.md`；写完在 `docs/README.md`
和大纲里各加一行指引。

## 3. 收口清单

- [ ] 代码/实验能复现，命令写进讲义
- [ ] 数据带日期、n、模型、口径
- [ ] "代价"段具体，不是形容词
- [ ] 负结果写清边界，没删
- [ ] `docs/README.md` + `教学大纲.md` 有指引
- [ ] `学习总结.md` 回写（若结论够硬）
- [ ] `问题清单.md` 补新坑（若踩了）
- [ ] 没有"现状/尚未"这类绝对时态
- [ ] 没有提交密钥/运行时数据

## 4. 红队清单（让独立 subagent 查）

把**原始数据 + 设计**给一个独立 subagent，不给你的结论，让它专门找：

1. 自变量真的拉开了吗？（弱模型真的更弱吗）
2. n 够吗？有没有把噪声当效应？
3. 判分器会不会假阳性/假阴性？期望值算对了吗？
4. 批判者/评委真的读到了候选答案吗？它会**把对的判错**、把**错的判对吗**？
   （2026-10-19 实测：同模型评委把 9 判成 11，又认同 771429；见正测设计稿 §11）
5. 两臂除了被测变量，还有别的不同吗？
6. 有没有测试集泄漏/提示词泄漏答案？
7. 失败样本被静默排除了吗？
8. 结论是否超出数据支持的强度？
9. 成本/延迟口径一致吗？

红队意见要么改设计，要么写进"诚实边界"。

## 5. DSH 工具怎么用

- **subagent**：做"独立批判者"（判据③）。给它原始数据和任务，不给结论；
  它的上下文独立，适合查"自我确认偏差"。
- **workflow**：并行跑多个 cell；每个 cell 独立、结果 schema 化。
  注意 token 是乘法的，先定预算。
- **background job**：长实验（>10 分钟）放后台，增量落盘，别阻塞对话。
- **skill / AGENTS.md**：本文件 + 仓库根 `AGENTS.md`；每个新会话自动带规矩。
- **session 工作区**：把 DSH 工作区指向 `~/ai-agent`，上述约定才会自动加载。

## 6. 反模式

- 为了"完整"把 10 种模式都实现一遍，却没有一个可证伪的问题。
- 用 LLM-as-judge 判本来能程序判的东西。
- 先写方案，再补"病"的证据。
- 把"平台跑通了"当成"我懂了"。
- 把旧结论当现状；不回写文档。
- 在没有 baseline 的情况下说"提升"。
