# 教学文档写作

> 这个仓库首先是**教学项目**，不是论文。默认写“让人看懂”的文档；
> 只有明确要交论文/正式报告时，才用 `paper-writing`。

## 0. 先定读者与目标

写之前先回答三句：

1. **写给谁看**：完全没接触过 Agent 的人？还是写过 demo 的人？
2. **看完要能做什么**：能讲清一个概念？能跑一个实验？能选一个模式？
3. **这次只讲哪一件事**：一张图、一节只讲一个点。

## 1. 默认结构（教学导读）

```markdown
# 标题：一句人话

> 这不是论文，是一张“先看懂、再动手”的地图。
> 适合：...
> 读法：先看三句话 → 再看图 → 按兴趣点进各章。

## 先看三句话
1. ...
2. ...
3. ...

## 概念小抄（先混个脸熟）
| 词 | 一句话 | 打个比方 |
|---|---|---|

## 图 1：...
![图 1｜...](../diagrams/xxx.png)
（看图说话：这张图只讲一件事……）

## 分节讲解
### 1. ...
（先讲“为什么需要它”，再讲“它怎么工作”，最后讲“代价”）

## 实测账
（表格：结论 / 数字 / 这说明什么）

## 边界与坑
（哪些情况不适用；负结果）

## 怎么读这套文档
（按目的给路径）

## 延伸阅读
（链到更深讲义，不堆参考文献）
```

## 2. 说人话的四条规则

1. **先解释，再用术语**。第一次出现 `RAG` / `embedding` / `MCP`，先用一句人话解释。
2. **多打比方，但别用比方代替定义**。比方负责“有感觉”，定义负责“能复现”。
3. **一段只讲一个点**。长段落拆成“是什么 / 为什么 / 代价”。
4. **数字照旧严谨**。token、墙钟、n、日期、失败模式一个不能少；
   但结论后面加一句“这说明什么”。

## 3. 概念解释模板

每个概念按这四行写：

```markdown
**是什么**：一句话定义。
**打个比方**：生活里的类比。
**为什么需要**：不用它会怎样。
**代价**：用了它多付什么。
```

## 4. 插图

- 一张图只讲一件事；主盒子 ≤ 7 个。
- 教学图优先用 `hand-drawn-diagram` skill（Notability 手绘风）。
- 图后必须有一段“看图说话”，不要只丢图。
- 图注写“图 N｜一句话”，不要写“如下图所示”。

## 5. 严谨性检查

- [ ] 第一次出现的术语有解释
- [ ] 每个模式/模块都写了“代价”
- [ ] 数字带日期、n、模型、口径
- [ ] 负结果和边界没被藏掉
- [ ] 没有“本文将”“综上所述”这类论文腔
- [ ] 没有为了顺口而夸大（“彻底解决”“完美”）
- [ ] 读者能按文档跑出至少一个结果

## 6. 与 paper-writing 的分工

- **默认**：`teaching-doc`（本 skill）。
- **明确要论文/正式报告**：再用 `paper-writing`；它保留摘要/关键词/参考文献那套格式。
- 两者可以复用同一批实测数据，但**不要**把教学文档写成论文缩略版。
