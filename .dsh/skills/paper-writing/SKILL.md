# 论文写作（正式模式）

> 默认写教学文档请用 `teaching-doc`；本 skill 只在明确要论文/正式报告时用。

> 本 skill 是**文档层**的流程；项目硬约束在仓库根 `AGENTS.md`，
> 成文细节在 `docs/00-索引/成文规矩.md`。开工前先读这两个。

## 0. 先定位：写的是哪一类文档

| 类型 | 用什么模板 | 例子 |
|---|---|---|
| **论文总纲** | §1：摘要 / 关键词 / 引言 / 相关工作 / 方法 / 实验 / 讨论 / 结论 / 参考 | 正式论文另建文件；教学文档见 `teaching-doc` |
| **单篇讲义** | §2：是什么 / 结构定位 / 为什么 / 代价 / 代码 / 实测账 | `docs/02-编排章/编排模式.md` |
| **调查类** | §2.2：问题 / 探针 / 结果 / 边界 / 代价 | `docs/02-编排章/数值题EC可靠性调查.md` |
| **索引/清单** | §3：表格 + 一句话 + 链接 | `docs/README.md`、`问题清单.md` |

## 1. 论文总纲模板

```markdown
# 标题：一个可复现的工程实践

> 作者 ｜ 日期 ｜ 代码：~/ai-agent

## 摘要
（问题 → 方法 → 主要结果 → 贡献；200–350 字，不写"本文将"套话）

## 关键词
Multi-Agent；ReAct；编排；记忆；评测；可观测性

## 1 引言
（问题、研究问题、贡献三条；链接到 README / 教学大纲）

## 2 相关工作
（框架、MCP、记忆、评测；链接到 99-番外；只写与本项目对照的部分）

## 3 系统设计
（本质 → 架构 → 编排 → 记忆 → 协议 → 观测；每节链接到对应讲义）

## 4 实验方法
（原则、对照组、指标、判分、n、预算；链接到 成文规矩 / 正测设计）

## 5 实验结果
（表格 + 每条的边界；正结果与负结果并列）

## 6 讨论
（代价结构、被证伪的判断、威胁与诚实边界）

## 7 结论
（不超过 9 条；每条可证伪/可复验）

## 参考文献
（只列真正引用的；格式统一）

## 附录
（代码地图、复现命令、问题清单）
```

## 2. 单篇讲义模板

### 2.1 标准六段

```markdown
# 章名 · 副标题

**一句话**：...
**适读**：...
**相关讲义**：...

## 1. 是什么
## 2. 结构定位
（谁控制流 × 信息怎么流）
## 3. 为什么这么设计
（替代方案为什么不行）
## 4. 代价（值钱那行）
（token / 延迟 / 复杂度 / 维护 / 失败模式）
## 5. 代码在哪
（文件 + 类/函数）
## 6. 怎么跑
（可直接复制的命令）
## 7. 实测账
（日期、n、模型、token、墙钟、分数；不是估计）
## 8. 踩过的坑
```

### 2.2 调查类（没有"代码"段时）

```markdown
# 章名 · 调查

## 1. 问题（要证伪哪句话）
## 2. 探针（v1 → v2 → v3，每版排掉什么缺陷）
## 3. 结果（原始数字 + 样本量）
## 4. 边界（结论支持到哪、不支持到哪）
## 5. 代价（token / 延迟 / 复杂度）
## 6. 产物（脚本、数据、后续）
```

## 3. 命名与链接规则

- **文件名用中文短名**，章目录保留 `00-索引`、`01-基础章` … 的编号。
- 技术缩写保留：`MCP`、`Agent`、`EC`、`Router`、`Fan-out`。
- 日期后缀用 `-YYYY-MM-DD`；不用空格、不用括号。
- **改名必须全库回写**：`git mv` + 替换旧 basename + 链接检查
  （0 broken / 0 orphan）。只改文件名不改引用 = 制造假链接。
- 链接用相对路径；跨章用 `../02-编排章/...`。
- 新文档必须同时进 `docs/README.md` 和 `00-索引/教学大纲.md`（若属于课程）。

## 4. 存量审视清单

- [ ] 链接：0 broken / 0 orphan
- [ ] 章前缀与所在目录一致（别把"实战章"放进"编排章"）
- [ ] 数字带日期、n、模型；没有"明显更快"这类形容词
- [ ] 没有过时数字（不要写死 `17 个模块` / `5000 行` / `27 份文档`）
- [ ] 旧模型/阈值已区分"历史语境"与"当前现状"（`v3`、`0.6`）
- [ ] 没有 `（现状）` / `尚未` 这类会腐坏的绝对时态
- [ ] 代价段具体；负结果写清边界
- [ ] 新文档已进索引；改名已回写

## 5. 导出

- 默认 Markdown 为源文件；**不要**为了排版把源文件改成 Word。
- 需要 Word/PDF 时，先读 `office` skill，再按 `office-docx` /
  `office-export-pdf` 的流程导出；导出物放 `docs/导出/`，源文件不动。

## 6. 反模式

- 文件名中文了，链接还是英文旧名。
- 每篇都套"摘要/引言/参考"，短讲义被撑成八股。
- 为了"论文感"堆引用，实际没读过。
- 改名后不跑链接检查。
- 把 Word 当源文件，Markdown 变成导出物。
